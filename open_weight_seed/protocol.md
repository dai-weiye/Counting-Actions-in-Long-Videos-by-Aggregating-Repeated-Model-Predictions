# Frame-sampling variation in a pinned local counting model

This study was specified before any of its 768 predictions. The original API development results and an earlier local three-identical-input control on these videos were already known. The local panel has its own outcomes and fixed compute settings. The API experiment retains its separate protocol and original slots.

## Fixed inputs and model

Use all 32 videos, all six groups, and the same four draw identifiers in each group from the previously fixed seed-replication design (SHA-256 d7f81f6a26ecb6fe567312564ef9f176f4fc351198943e837c760273fb437f8c). Each original stream selects 128 temporal indices from the video's uniform 256-frame pool. From each sorted list of 128 retain the 16 indices at positions numpy.linspace(0,127,16).astype(int). Re-decode the original video RGB frames with OpenCV. Use Pillow Lanczos thumbnail resizing, maintaining aspect ratio and a maximum image side of 224 pixels. Verify each input source video against the original's SHA-256. An optional in-memory pool reuses identical source pixels across calls of the same video.

Use MLX Community Qwen2-VL-2B-Instruct 4-bit, revision 01af461cdb9574acc09084a0ef94e216e142b085, with the previously validated model-file manifest. For each slot use the established 16-image chat template, original benchmark question and four options, greedy decoding, temperature zero, MLX seed 0 reset before every call and at most eight new tokens. Run a new forward/generation for every slot, serially on one device, in the locked filename rank followed by group and call order. No model output is reused between separate generations. A complete final response closes its slot even if the output is blank or outside the listed answers. Resume unrecorded slots after an environmental interruption.

Record the complete decoded final string, option count, status, finish reason, ordered source indices, ordered RGB pixel hash with image dimensions, prompt digest, model revision and runtime versions. Study inference receives only the public question and options. Use the archived labels once all slots have closed.

## Endpoints

For each group, score four numeric reports with the same fixed integer rule as the API seed study (smallest maximizing candidate in 1 through 5), comparing with the average of all four constituent single-call accuracies. The unit for across-group variability is one set of four seed streams, evaluated on the same videos. Report the six gains, their mean, range and sample standard deviation using the intersection of videos with all four valid reports in all six groups. Report an interval for the mean across the six groups by resampling those common videos in pairs, 20,000 replicates, PCG64 seed 0 and percentile endpoints at 2.5% and 97.5%. Report the within-group valid denominators and the two fixed all-32-question yields from the API plan (four valid reports required, and fallback to all available reports). Reuse its vote, tie and best-single diagnostics.

Also count the common-cohort videos whose 24 input draws produced at least two distinct numeric answers and those whose six four-report estimates change across groups. Report the proportion of unordered valid within-video report pairs with different counts, pooling all eligible pairs. The earlier independent local identical-input control provides the directly observed repeatability reference at this same checkpoint and visual budget. Outcomes describe this checkpoint, 16-frame inputs and these 32 videos. Cross-model absolute accuracies use different visual and decoding budgets.
