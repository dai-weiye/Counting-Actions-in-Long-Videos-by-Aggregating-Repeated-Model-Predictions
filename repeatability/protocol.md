# Repeatability of identical video requests

This protocol was fixed before collection of the repeat responses. The earlier fourth-call experiment and its aggregate results were known. The cohort is all 103 questions formerly held out from tuning. For each question replay once the uniform 128-frame request from the fourth-call study. Check the SHA-256 of the complete request bytes against the stored digest before sending. Use the same endpoint, alias, JPEGs, prompt, option order, temperature zero, reasoning setting and 8,192-token maximum. Retain the first complete HTTP response including a blank or unsupported final, with the transient transport retry policy of the fourth-call study. Recover the two unavailable source files from their recorded hashes. Stop on receipt of one terminal status per question, regardless of accuracy or agreement.

The primary quantity is the number of different numerical answers among pairs with two usable final numbers. Also report agreement when each unusable final is retained as a status, valid and blank counts in each round, consistency of the served alias and response fingerprint, and a Wilson 95% score interval for conditional numerical disagreement. The unit is a question. No gold labels, tuning, accuracy tests, matching on model output, or replacements after a blank response are involved. A fingerprint identifies a provider-reported service configuration. Matching request digests and fingerprints isolate variability visible to the API client; this comparison does not identify a particular operation inside the server.
